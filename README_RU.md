# CCBot Fork — русская редакция

[English README](README.md) · [中文文档](README_CN.md)

Форк [ccmux](https://github.com/six-ddc/ccmux) с русской локализацией, чистым выводом, автоотправкой файлов, emoji-реакциями и голосовой транскрипцией через Deepgram.

---

## Что нового в форке

Оригинальный CCBot пересылает в Telegram всё подряд: каждый вызов `Bash(...)`, `Read(...)`, JSON-ответы MCP-серверов с ключами API в теле. На практике это неудобно — лента забивается техническим шумом, а не результатами работы. Форк включает режим чистого вывода по умолчанию: в Telegram приходят только финальные ответы Claude, интерактивные запросы и файлы. Плюс к этому — полный русский интерфейс, реакции как быстрый фидбек, автоматическая отправка документов и Deepgram вместо OpenAI Whisper для голосовых сообщений.

---

## Быстрый старт

**1. Создайте Telegram-бота**

Напишите [@BotFather](https://t.me/BotFather), создайте бота и получите токен. В настройках бота включите **Threaded Mode** (Settings → Bot Settings).

**2. Узнайте свой Telegram ID**

Напишите [@userinfobot](https://t.me/userinfobot) — он пришлёт ваш числовой ID.

**3. Создайте `.env`**

```bash
mkdir -p ~/.ccbot
cat > ~/.ccbot/.env << 'EOF'
TELEGRAM_BOT_TOKEN=ваш_токен_от_botfather
ALLOWED_USERS=ваш_telegram_id
EOF
```

**4. Установите и настройте hook**

```bash
# Через uv (рекомендуется)
uv tool install git+https://github.com/your-fork/ccbot.git

# Или из исходников
git clone https://github.com/your-fork/ccbot.git && cd ccbot && uv sync

# Установить SessionStart hook
ccbot hook --install
```

**5. Запустите**

```bash
ccbot
# или из исходников:
uv run ccbot
```

Откройте Telegram, создайте topic в группе с ботом, отправьте любое сообщение — появится браузер папок для выбора проекта.

## Возможности

### Чистый вывод

По умолчанию включён (`CCBOT_CLEAN_OUTPUT=true`). Фильтрует технический шум, показывает только ответы Claude.

**Что фильтруется:**
- `tool_use` — вызовы инструментов: `Bash(find ...)`, `Read(...)`, `Grep(...)`, MCP-запросы
- `tool_result` — вывод команд, содержимое файлов, JSON-ответы API
- `thinking` — внутренние рассуждения Claude (цепочка мыслей)
- `local_command` — активации скиллов, вывод хуков

**Что проходит:**
- Финальные текстовые ответы Claude
- Интерактивные запросы: `AskUserQuestion`, `ExitPlanMode` — требуют ответа
- Изображения из tool results (скриншоты, сгенерированные картинки)
- Файлы-документы (автоотправка при записи через Write-инструмент)

**Статус работы:**

Пока Claude думает — одно сообщение "⏳ Работаю…" вместо потока инструментов. Обновляется на месте через `edit_message_text`, не засоряет чат.

---

### Автоотправка файлов

Когда Claude записывает документ через Write-инструмент, файл автоматически отправляется в Telegram-topic как документ.

**Поддерживаемые расширения:** `.md` `.txt` `.pdf` `.docx` `.doc` `.xlsx` `.xls` `.csv` `.html` `.htm` `.rtf` `.epub`

**Определение намерения по фразе:** Если в сообщении есть фразы вроде "пришли в тг", "скинь в тг", "отправь в телеграм" (11 вариантов), бот автоматически подсказывает Claude сохранить результат в файл. Claude записывает файл — бот его отправляет.

**Безопасность файлов:**
- Путь разрешается через `Path.expanduser().resolve()` перед любой операцией
- Двойная проверка `allowed_roots` — в session_monitor и в bot.py
- Заблокированы чувствительные имена файлов: `.env`, `credentials`, `id_rsa`, `id_ed25519`, `id_dsa`, `.netrc`, `.pgpass`, `session_map.json`, `state.json`, `monitor_state.json`
- Конфигурационный каталог (`~/.ccbot/`) исключён полностью
- `.json` и `.xml` исключены из отправляемых расширений (слишком много credential-файлов используют эти форматы)
- Размер: больше 0 байт и меньше 50 МБ
- Дедупликация по resolved-пути — один файл не отправится дважды через разные пути

### Автоочистка мёртвых сессий

Раньше после `/exit` или краша Claude tmux-окна оставались висеть с мёртвыми шеллами и накапливались.

**Как работает обнаружение:** Статус-поллинг (каждую секунду) проверяет `pgrep -P <pane_pid>` — если у шелла нет дочерних процессов, Claude завершился.

**Grace period 5 секунд:** Прежде чем убить сессию, бот ждёт 5 секунд стабильного "не запущен". Это защищает от ложных срабатываний при кратких переходах (например, Claude перезапускается после `/clear`). Таймер сбрасывается, если Claude снова обнаруживается как живой.

**Последовательность очистки:**
1. Убить tmux-окно
2. Отвязать thread от topic
3. Очистить состояние topic (статусные сообщения, интерактивный UI)
4. Отправить уведомление: "Сессия завершена. Напиши сюда чтобы начать новую или возобновить."

**Возобновление:** После очистки пишете в тот же topic → браузер папок → выбор существующей сессии → `--resume <session_id>`.

### Голосовые сообщения через Deepgram

Заменён OpenAI Whisper на Deepgram Nova-3. Транскрипция работает быстрее и лучше справляется с русским языком.

- Модель: `nova-3`, язык: `ru`
- Вход: сырые OGG-байты (`Content-Type: audio/ogg`)
- Аутентификация: `Token <key>` (не Bearer)
- Ошибки не раскрывают тело ответа API

Настройка: добавьте `DEEPGRAM_API_KEY` в `.env`. Без ключа голосовые сообщения просто не работают, остальное функционирует нормально.

### Русская локализация

Охват: 13 команд, браузер папок, пикеры сессий, сообщения об ошибках.

**13 команд бота:**

| Команда | Описание |
|---------|----------|
| `/start` | Приветствие и справка |
| `/history` | История сообщений сессии |
| `/screenshot` | Скриншот терминала |
| `/esc` | Прервать Claude (Escape) |
| `/kill` | Завершить сессию и удалить топик |
| `/unbind` | Отвязать топик (окно останется) |
| `/usage` | Остаток лимита Claude Code |
| `/clear` | Очистить историю диалога |
| `/compact` | Сжать контекст разговора |
| `/cost` | Показать расход токенов |
| `/help` | Справка Claude Code |
| `/memory` | Редактировать CLAUDE.md |
| `/model` | Сменить модель ИИ |

Браузер папок, выбор окон, выбор сессий, все сообщения об ошибках — всё на русском.

## Безопасность

Форк прошёл аудит с 4 параллельными агентами, закрыто 19 уязвимостей.

**Ключевые меры:**
- Лимит 30 сообщений / 60 секунд на пользователя (все каналы: текст, фото, голос, команды)
- Null-байты (`\x00`) и `\r` вырезаются из tmux `send_keys` — защита от tmux-инъекции
- UUID regex + `shlex.quote()` для `--resume` session IDs — защита от command injection через `session_map.json`
- Браузер папок ограничен `CCBOT_ALLOWED_ROOTS`, блокирует `..` на границе — проверка в момент подтверждения, не только при навигации
- Чувствительные переменные (`TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`, `DEEPGRAM_API_KEY` и др.) удаляются из `os.environ` сразу после считывания — дочерние процессы их не наследуют
- Лог создаётся с `chmod 600` (только владелец)
- `_msg_thread_map` ограничен 10k записей с TTL-вытеснением

## Конфигурация

Файл: `~/.ccbot/.env` (или `.env` в рабочей директории — приоритет выше).

### Обязательные

| Переменная | Описание |
|-----------|----------|
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather |
| `ALLOWED_USERS` | Telegram user ID через запятую |

### Опциональные

| Переменная | По умолчанию | Описание |
|-----------|--------------|----------|
| `CCBOT_DIR` | `~/.ccbot` | Каталог конфигурации и state-файлов |
| `TMUX_SESSION_NAME` | `ccbot` | Имя tmux-сессии |
| `CLAUDE_COMMAND` | `claude` | Команда запуска Claude в новых окнах |
| `MONITOR_POLL_INTERVAL` | `2.0` | Интервал поллинга в секундах (минимум 0.5) |
| `CCBOT_CLEAN_OUTPUT` | `true` | Фильтровать tool-спам, показывать только ответы |
| `CCBOT_ALLOWED_ROOTS` | `~` | Границы браузера папок и автоотправки файлов (через запятую) |
| `CCBOT_SHOW_USER_MESSAGES` | `false` | Эхо сообщений пользователя с префиксом |
| `CCBOT_SHOW_HIDDEN_DIRS` | `false` | Показывать скрытые (dot) папки в браузере |
| `DEEPGRAM_API_KEY` | — | API-ключ Deepgram для транскрипции голосовых сообщений |
| `CCBOT_CLAUDE_PROJECTS_PATH` | `~/.claude/projects` | Путь к проектам Claude (для нестандартных установок) |
| `CLAUDE_CONFIG_DIR` | — | Каталог конфигурации Claude (альтернатива CCBOT_CLAUDE_PROJECTS_PATH) |
| `OPENAI_API_KEY` | — | Устаревший ключ OpenAI (не используется для транскрипции) |

**Совет для VPS без интерактивного терминала:**

```bash
CLAUDE_COMMAND=IS_SANDBOX=1 claude --dangerously-skip-permissions
```

## Архитектура

```
┌─────────────────────────────────────────────────────────┐
│                    Telegram Bot (bot.py)                │
│  1 topic = 1 tmux window = 1 Claude session            │
│  Реакции, rate limiting, автоотправка файлов,          │
│  русский UI, clean output, inline keyboards             │
├──────────────────────────┬──────────────────────────────┤
│   SessionMonitor         │   TmuxManager                │
│   Поллинг JSONL каждые   │   list/create/kill windows   │
│   2 сек, фильтрация      │   send_keys, capture_pane    │
│   clean output, детект   │   is_claude_running (pgrep)  │
│   файлов, рабочий статус │   input sanitization         │
└──────────────┬───────────┴──────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────────────────┐
│              Claude Code (tmux window)                  │
│   ~/.claude/projects/.../*.jsonl  ←  SessionStart hook │
└─────────────────────────────────────────────────────────┘

Маппинг:
  Topic ID (Telegram) → Window ID (tmux @N) → Session ID (Claude)
  thread_bindings в state.json         session_map.json (hook)

State-файлы (~/.ccbot/):
  state.json          — привязки topic/window, display names, read offsets
  session_map.json    — таблица window_id → session_id (пишет hook)
  monitor_state.json  — byte-offset по JSONL-файлам (предотвращает дубли)
  ccbot.log           — ротируемый лог (1 МБ × 3 файла, chmod 600)
```
